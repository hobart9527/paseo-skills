## 方案选择

1. 只修文案：成本最低，但仍让模型手工同步两个集合，不足以处理主要返工。
2. **规则对齐 + 小型只读派生辅助 + 准确结果采集（选定方向）**：直接处理已观测摩擦，不替模型作语义决定。
3. 重写契约生成器、shell 解析器或多作者调度：成本和变更面过大，本轮不做。

## 有界改动

### 1. 对齐作者、schema、模板

明确每个声明 SCEN 都有验收行；多个场景可复用真实入口和验证命令，不要求为每行新增测试。tasks 的 Scenarios 是认领来源，acceptance 的 Tasks 是其投影；每行列出的任务必须属于认领集合，同一场景所有行的任务并集必须覆盖全部认领者。Entry、Verify、Required 仍由作者判断，不能统一设为 Required=no 过关。

区分新场景 ID、baseline 的 MODIFIED/REMOVED 身份复用、与 active change 的内容冲突。既有冲突必须暴露及协调；不能仅改名伪装成独立行为。保留当前保守内容比较，不改碰撞语义，不增加 archive 扫描或注册服务。

### 2. 只读派生辅助

提供一个只读命令，复用现有 tasks 解析和场景声明发现逻辑，列出声明场景、认领任务、已有验收关系及缺口；可输出 Scenario/Tasks 候选供作者填表。不要另写不同语义的 Markdown 扫描器；必要抽取仅限共享发现/解析函数，保持现有门禁行为与回归测试。

命令不执行 Verify、不改文件、不重编号、不改任务认领、不创造 scope/依赖；不生成 Entry、业务预期、Required 或测试充分性结论。候选不是可冻结的完整验收行，不替代 structural 或 R0。多行场景保持原行语义，不将全部认领者强塞进每一行。

辅助输出按同一批读入内容计算，只作当前草稿建议；内容改变后须重新生成。不得产出第二份需人工维护的 ownership 文件。遇到解析错误明确失败，不输出可误当有效的完整候选。

### 3. Verify 识别与多包回归

先以真实命令建立失败用例，再有界修复 npm 的 `--prefix <dir> test` 等此次明确支持的形态：工作目录参数不是测试目标；显式窄测试目标仍须正确解析。读取并测试 freeze-check 与 merge-task 两个调用方，避免将窄回归错误跳过。

不扩展成通用 shell 语法解析，不凭未知命令证明安全，不用包装脚本隐藏宽验证。保持现有至多一条全量 leg 约束：sink 的 Verify 使用真实、可运行的窄集成测试或一条受支持的全量命令；其余包的全量回归由最终验收运行并显式列出。不为绕门禁扩 scope、增虚假任务或删除必要回归。若仓库命令无法在此范围内表达，报告不支持，不继续扩解析器。

### 4. 结果与时间采集

复用 `freeze-check --structural --json`，调用方直接保留 stdout、stderr、真实进程退出码和被检查的 Git 状态；不通过 `tail` 的状态推断检查结果。未提交草稿记录为草稿，提交后结构成功才可报告 COMPLETE。

下次实验控制面在作者起点后 25 分钟设置一次停止事件，30 分钟仅作必要恢复对账，不轮询。分别记录计划截止、指令送达、实际停止与快照提交时间；通知延迟不是作者完成。此项只调整实验编排与 brief，不改生产调度器，不声称事件投递等于强制终止。

## 验收与非目标

- 用实际模板填写的多场景、多任务包验证全覆盖和认领一致性；保留漏行、额外 owner、跨行掩盖错误的负例。不只断言模板包含某句话。
- 派生候选稳定、只读，场景/任务解析错误不静默忽略；现有 Entry/Verify/Required 不被覆盖。机械一致不等于语义正确。
- Verify 用例覆盖真实 npm prefix 全量命令、明确窄目标、既有命令；核对 merge replay 不漏窄测试。未知 shell 不被误称已理解。
- 检查失败退出码保持非零，advisory 与 blocker 分开记录。
- D4 回放只能衡量工具和反馈修复，不计新作者成绩、不修改原快照。D5 在修复与独立审查完成、部署版本确定后再单独启动；同基线、输入、预算，不提供 D4 答案，记录模型配置与实际可观测模型。
- 作者阶段目标仍为 ≤30 分钟，但不保证单次达标。分别报告结构修复、R0、总耗时；不以减少行数、伪造依赖、放松语义标准取得速度。
- 不续修 D4，不实施 approval-hub 业务，不增加 reviewer 层、不改变 CP-1/CP-2，不自动 push、合并或清理。
