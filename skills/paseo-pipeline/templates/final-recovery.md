4. Create `task/<change>/<new-T-id>` from the approved amended integration tip; install the hook and dependencies. Dispatch `gaogong` with `templates/worker.md`. Run `pipeline-run.mjs merge <change-dir> <new-T-id>` in integration. The normal scope, provenance, frozen Verify, regression and Done gates apply unchanged. Never cherry-pick around them.
5. Once all tasks are Done and integration is clean, capture `git rev-parse HEAD` as the new final SHA. Rerun the full suite and every `Required=yes` acceptance command at that exact SHA, and have the original FINAL reviewer check the fix diff and integrated result at that same SHA. Record commands, results, reviewer identity, verdict and full SHA. If the reviewer finds another blocker, repeat steps 3-5; no pass carries over to a new SHA.
6. Immediately before CP-2, verify integration HEAD still equals the recorded SHA, the worktree is clean, main has not moved since review, all commands passed, and FINAL has no blocker at that SHA. Otherwise repeat step 5 on the new base/SHA. Report evidence and task SHAs; CP-2 stays human.

## Interrupted merge marker after Done

If `plan` shows the task Done but a pending ref remains after a crash, inspect the clean integration worktree, first-parent merge commit, Done source, and task tip. A verified completed merge needs no retry; leave the stale ref as evidence. Never clear it to bypass a gate. A dirty worktree is not proof of committed Done; reconcile it first.
