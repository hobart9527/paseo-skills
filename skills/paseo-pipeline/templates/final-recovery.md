   **Batch.** One round's DEVIATIONs become one amendment and one repair wave: a new task per coherent fix, split by domain into parallel tasks where Write scopes allow. Record the finding, SCEN, narrow Write scope, dependencies and executable Verify; retain existing Done evidence. **A repair task normally overlaps a Done task's Write scope, so it must name that task in `Depends on`** — `freeze-check --structural` rejects an overlapping pair with `SCOPE_CONFLICT` when neither depends on the other. Repairs depend on each other only when their own scopes overlap; do not chain them serially. The author commits the contract-only amendment on integration; run `freeze-check.mjs <change-dir> --structural`; a new interface/security boundary needs delta-only amendment R0 against its parent SHA (one round). Obtain human CP-1 approval of the amendment before dispatch; if the contract changes after approval, obtain approval again. Every approval binds to a SHA in `run-log.md`; an "approach only" approval is not one. The existing pipeline continues even if this small repair alone would not qualify as a new Tier 3 pipeline.
   **Pre-authorized budget.** At CP-1 the human may pre-approve "up to 1 FINAL repair wave of ≤N tasks, DEVIATION only", recorded with the contract SHA in `run-log.md`. Within it, repair tasks need no per-task re-freeze approval. Beyond it, or for any CONTRACT_GAP, ask.
4. Create `task/<change>/<new-T-id>` from the approved amended integration tip; install the hook and dependencies. Dispatch `gaogong` with `templates/worker.md`. Run `pipeline-run.mjs merge <change-dir> <new-T-id>` in integration. The normal scope, provenance, frozen Verify, regression and Done gates apply unchanged. Never cherry-pick around them.
5. Once all tasks are Done and integration is clean, capture `git rev-parse HEAD` as the new final SHA. Rerun the full suite and every `Required=yes` acceptance command at that exact SHA, and have the FINAL reviewer run round 2 at the same SHA: delta only (fix diff, affected behavior, open ledger items). Use one `anchasi` session for all FINAL rounds of a change. A replacement (same profile, never the implementer's model) reads the ledger first, inherits the round budget, and the reason for replacement is recorded with its agent id. Record commands, results, reviewer identity, verdict and full SHA; no pass carries over to a new SHA.
   **Bound: at most 2 FINAL rounds per change** (round 1 full, round 2 delta). After round 2 with any NOT_MET, the human must choose one: (a) accept residual risk — `FINAL: human-accept(@<sha>)` in `review.md`, open items and reason in `rulings.md`, `Approval: FINAL residual risk accepted for <sha> — <reason>` in `run-log.md` (mirrors R0; never written as a reviewer pass; checked by the human at CP-2); (b) reopen at contract level — delta R0 + CP-1, then a new repair wave whose re-review is again delta only; (c) terminate the change. There is no fourth default: no unbounded repeat, no silent stall.
6. Immediately before CP-2, verify integration HEAD still equals the recorded SHA, the worktree is clean, main has not moved since review, all commands passed, and FINAL has no unaccepted blocker at that SHA. Otherwise redo the evidence at the new base/SHA as a delta review of what changed; it does not add a FINAL round. Report evidence and task SHAs; CP-2 stays human.

## Interrupted merge marker after Done

If `plan` shows the task Done but a pending ref remains after a crash, inspect the clean integration worktree, first-parent merge commit, Done source, and task tip. A verified completed merge needs no retry; leave the stale ref as evidence. Never clear it to bypass a gate. A dirty worktree is not proof of committed Done; reconcile it first.
